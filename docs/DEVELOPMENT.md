# Developing fm

How fm is put together, why it's built this way, and what to watch out for when changing it.
For building and using it, see the [README](../README.md).

## Goal

fm has to look like layout A of the mockup ([`mockup.png`](mockup.png)) while behaving like the
other windows on the desktop. The rules that came out of using it:

- **Geometry from the mockup, sizes from the system.** The window layout uses mockup pixels × `u`
  (0.85). Text, sidebar rows, label pills and inline rename use `tu` = system font px / 13.5 instead,
  so they match other apps (SF Pro Text 10 pt = 13.33 px). The traffic lights are fixed at the size
  of the KWin (WhiteSur) title bar buttons: 13.3 px circles, 26 px apart centre to centre, measured
  from a screenshot of another window.
- **IRIX inside, normal outside.** The IRIX icons are only for files inside the window. The menu
  entry and the window icon use the icon theme's `system-file-manager`, so the dock shows the usual
  Finder icon.
- **Native where it shows.** Context menus and the global menu are `Qt.labs.platform` menus, so they
  get the system style (Kvantum) and appear in the top bar's global menu.
- **Touchpad everywhere.** Every scrollable thing takes two-finger scrolling (see Scrolling).

## Architecture

```

             IRIXFM_SNAPSHOT mode
fm.h/.cpp    the `Fm` object exposed to QML:
               updateWindow()  blur behind + input mask in the rounded shape (KWindowEffects),
                               compositor-drawn shadow (KWindowShadow, tiles cut from a blurred image)
               kind()          folder | app (.desktop) | image | exe | doc, from QMimeDatabase
               desktopInfo()   Name= and Icon= of a .desktop file
               open()          KIO::OpenUrlJob (default app; runs .desktop files and executables)
               trash/copy/paste/drop/makeFolder/rename  KIO jobs, progress in Plasma's notifications
qml/Main.qml the window: state, navigation, selection, glass, sidebar, toolbar, grid + list, status bar,
             menus, shortcuts
qml/EdgeRing.qml     the glass edge: a ring filled with a top-to-bottom gradient (brightest at the top)
qml/Pill.qml         toolbar pill = tint + EdgeRing
qml/TrafficLights.qml close / minimise / zoom, with glyphs on hover
qml/Thumbwheel.qml   the SGI thumbwheel: ridges placed on a rotating cylinder (sin for x, cos for shading)
qml/Rename.qml       inline rename field (F2)
qml/SplitPane.qml    the split view's second side (own tabs, view, icon size); PaneHeader.qml its ‹ ↑ path
qml/TabStrip.qml     IRIX notebook tabs (NotebookTab.qml)
qml/BrowserView.qml  web tabs (Qt WebEngine), loaded on first use
qml/IconPicker.qml   Icon… for sidebar entries (emoji / app icons)

             for the selection glow. Carpets and glyphs are separate layers.

tools/       make_icons.py, make_mockup.py (renders docs/mockup.png over docs/bg.jpg)
```

### The glass

The window is frameless and transparent. KWin blurs whatever is behind the rounded shape that
`updateWindow()` registers. On top of that, one `Shape` paints the body tint with **holes** where the
sidebar and the four toolbar pills sit; those draw their own lighter tint. That reproduces the
mockup, where the sidebar and pills are separate glass layers over the wallpaper, not tint stacked
on tint. If you move or resize a pill, its hole follows because the `PathRectangle`s bind to the
pill's geometry.

`updateWindow()` runs on every resize and on maximise/restore. Maximised, the corner radius is 0 and
there's no shadow.

### Selection, dragging and the rubber band

Selection is an object `path -> true` on the window (`win.selection`); bindings depend on the
object, so always assign a new object rather than mutating it. The grid is **non-interactive** so a
left drag in empty space draws a rubber band (a `MouseArea` at `z: -1` on the `GridView`, under the
delegates). Dragging an item uses `Drag.Automatic` with a `text/uri-list`, so files can be dropped
into other apps; drops onto folders or empty space go through KIO (Shift moves).

### Scrolling

Because the grid is non-interactive, Qt's own wheel handling is off, so `WheelHandler`s do it:

- `acceptedDevices: PointerDevice.Mouse | PointerDevice.TouchPad`. Without `TouchPad` the touchpad
  is ignored.
- Touchpads send `pixelDelta` (used 1:1); mouse wheels send `angleDelta` of 120 per notch (60 px).
- `win.scroll(view, event)` clamps to `originY - topMargin … originY + contentHeight + bottomMargin - height`.
  Don't clamp at 0: the list view's overlay header makes `originY` negative.
- The list view uses the same handler, so both views scroll the same way.
- A `WheelHandler` reacts to **one orientation** only (vertical by default). The thumbwheel is
  horizontal, so it has one handler per axis: sideways swipes are the natural gesture for it.
  About 400 px of swipe covers the whole icon-size range; a mouse notch is 6 %.

`make test` checks all of this with simulated touchpad and mouse events on an off-screen window.

### Path bar

`pathPill` shows clickable crumbs; clicking the current folder or the empty part, Ctrl+L, Ctrl+Shift+G
or typing `/`/`~` in the file view swaps them for `pathInput` (`win.editPath()`). `Fm::resolvePath()`
turns the text into `{ok, dir, file}` (absolute, `~`, relative to the current folder, `file://`);
`Fm::completePath()` completes the last component against folder names (case-insensitive, hidden
ones after a dot). The greyed-out rest of the completion is a `Text` placed at the end of the
input. A file path selects the file once the folder model has loaded (`selectAfterLoad`).

### Sidebar

The sidebar is data: `win.places` = sections `{title, color, items: [{label, path | action}]}`,
saved as JSON in the settings (`placesJson`; empty = `defaultPlaces()`). Paths under home are
stored as `~/…`. `placeRows` flattens it into header / item / empty-hint rows for a `ListView`;
header rows carry the 30-unit gap above them so the baselines match the mockup. Edits go through
`placeAdd/Remove/Rename/Move/MoveTo/resetPlaces`, which always write a new JSON string (bindings
follow `placesJson`). The list is non-interactive and scrolls with the same `win.scroll()` as the
file views.

### Finder commands

See [FINDER-FEATURES.md](FINDER-FEATURES.md) for the full plan. Implementation notes:

- **Quick Look** (`qml/QuickLook.qml`) is an overlay inside the window, not a separate window, so the
  file view keeps the keyboard: arrow keys move the selection and `onSelectionChanged` points
  `win.quickLook` at the focused item. The kind comes from `Fm::info()` (MIME type); text previews
  read at most 256 KB and are skipped for binary files.
- **Get Info** (`qml/InfoWindow.qml`) is a real window per item, like Finder; it takes the keyboard
  while open. Folder sizes come from `Fm::folderSize()` → `folderSizeReady`.
- **Undo** uses `KIO::FileUndoManager`: every copy/move/trash/rename/duplicate/alias job goes
  through `undoable()` (a `CopyJob`) and mkdir is recorded with `recordJob`. Aliases use
  `KIO::linkAs` (a CopyJob) because a `symlink` job recorded by hand isn't undone. There is no redo
  in KIO.
- **New items get selected** through `win.selectWhenReady(paths)`: the folder model fills in
  asynchronously, so the selection is applied once every path has an index.
- **Type to select** collects letters for 1 s (`typeAhead`); a space only continues a name while
  typing, otherwise it opens Quick Look.

### Phase 2

- **Results use the normal views.** Search and tag hits go into `resultsModel` (a `ListModel` with
  the folder model's role names), and the grid and list switch their model while searching. All
  selection code goes through `win.itemAt(i, role)`, `win.itemCount` and `win.indexOfPath(p)`, which
  pick the folder or the results.
- **Folding**: clicking a sidebar section title toggles it in `collapsedJson` (saved);
  `placeRows` then only emits the header.
- **Search** no longer filters the folder model (`FolderListModel.nameFilters` never hides
  folders, which made search look broken). Typing shows a results list fed by `Fm::startSearch()`, a
  `QDirIterator` scan in a worker thread that sends batches (`searchBatch`) and stops at 2000 hits;
  a generation counter cancels an older scan. The scope bar picks this folder / with subfolders /
  Home (`searchScope`, saved). `focusedPath()` follows the result cursor, so Quick Look, Get Info and
  copy work on results.
- **Trash** is the home trash folder (`Fm.trashDir`, `$XDG_DATA_HOME/Trash/files`) listed like any
  folder; Put Back uses `KIO::restoreFromTrash` on `trash:/0-<name>`, Empty uses `KIO::emptyTrash`.
  Older saved sidebars get a Trash entry once (`trashAdded`). KIO won't trash files on tmpfs
  (`/tmp`); it asks to delete them instead.
- **Drives** come from Solid (`Fm.volumes`): hot-pluggable or removable storage only. They're
  appended to Locations at run time, not saved.
- **Layout**: `sideShift` moves the toolbar when the sidebar is hidden (it keeps room for the traffic
  lights), `contentShift` moves the files, scope bar and status bar to the window's left edge so they
  use the whole width, and `previewW` makes room for the preview pane; all three are animated; the glass tint has holes for the sidebar and the preview pane.
- **Folder sizes** go through a queue in `Fm` (3 `DirectorySizeJob`s at a time) into
  `win.folderSizes`, and are **cached** (`~/.cache/irixfm/folder-sizes.json`, at most 5000 folders):
  a folder whose own mtime hasn't changed and was counted less than an hour ago answers at once;
  otherwise the cached size shows while it's recounted (`Fm.cachedFolderSize`). KDE has no database
  of folder sizes (Baloo indexes files, not folder totals), so fm keeps its own. Note a folder's
  mtime only changes when its direct entries change, hence the one-hour limit.
- **Kind** (`Fm::kind`) looks at the file name first (`QMimeDatabase::MatchExtension`) and only
  reads the file when the name says nothing.
- **Compress / Expand** use KArchive in a worker thread (`archiveDone` selects the result).
- **Settings are saved immediately** for the sidebar (`settings.sync()`), and `main.cpp` quits
  cleanly on SIGTERM/SIGINT (KSignalHandler), so `pkill irixfm` no longer loses changes.

### Tags

See [TAGS.md](TAGS.md) for the behaviour. Implementation:

- Tags live on the files (`Fm::tags/setTags/addTag/removeTag`, xattr `user.xdg.tags`,
  comma-separated). The names, Nord colours, order and sidebar visibility live in the settings
  (`tagsJson` → `win.tagDefs`); a tag found on a file but not defined shows grey.
- Views read tags with `win.tagsOf(path)` = `Fm.tags(path, win.tagRev)`; `Fm::tagsChanged` bumps
  `tagRev`, which re-evaluates every binding. The tinted carpet is a `Shape` in the carpet's outline
  (a shader effect rendered nothing off-screen).
- Finding: `Fm::startTagSearch(tag, here)` checks candidates from fm's index
  (`$XDG_DATA_HOME/irixfm/tags.json`, pruned of missing files at start), `baloosearch6 tag:<name>` and the folder on screen, and
  re-reads each file's tags before listing it. `tag:Name` in the search field or a click in the
  sidebar starts it; the scope bar then shows the tag.
- Rename / Delete Tag rewrite the tag on every candidate file (`renameTagEverywhere`,
  `deleteTagEverywhere`).
- Menus show colour dots from `icons/tag-<hex>.svg` (generated for the 10 Nord colours).

### Tabs and the IRIX reference

What IRIX 6.2 actually did (checked against SGI's *Desktop User's Guide* 007-1342, *Indigo Magic
User Interface Guidelines* 007-2167 and *Desktop Integration Guide* 007-2006):
- The square below the size thumbwheel is the thumbwheel's **home button**: "To revert to the
  original size, click the small box below the thumbwheel." fm's `homeButton` sets `wheelValue` back
  to `defaultWheel`.
- The notebook tabs were the **Icon Catalog's pages** (Applications, Collaboration, Demos, …; Page Up
  / Page Down switch; a stack of unnumbered tabs opens a page menu when they don't fit). Directory
  views had no tabs. fm uses that look for Finder-style tabs, Ctrl+PgUp/PgDn echo IRIX's keys and
  "////" opens the list of tabs.

How tabs work:
- The **active tab is the live window state** (`dir`, `backStack`/`fwdStack`, `selection`,
  `anchorIndex`, `search.text`); the other tabs are snapshots in `win.tabs`. `switchTab()` =
  `saveTab()` + `loadTab(i)`. That keeps every binding, menu and shortcut working unchanged.
- `loadTab` closes transient state (rename, Quick Look, path editing, type-ahead), restores the
  history and search, re-selects the saved selection once the folder model has the items
  (`selectWhenReady`) and restores the scroll position (`pendingScrollY`, applied when the model is
  Ready and the selection is done).
- `openFolder(path)` gives a sidebar place a tab: `findTab` (same folder, same search) or `newTab`.
  Everything opened inside a tab uses `go()` and stays in the tab (double-click, Enter, back/forward,
  crumbs, typed paths, spring-loading); Ctrl+double-click and middle-click use `openInNewTab`.
- `onDirChanged` refreshes the active snapshot and `persistTabs()` writes `{dir, back, fwd,
  search}` to the settings immediately. `Fm.restoreSession` (no folder argument) restores them.
- `TabStrip.qml` is a non-interactive horizontal `ListView` of `NotebookTab`s (`spacing: -s`, so
  the slanted sides interleave), drawing the page edge with a gap where the active tab joins it.

### Split view

The two sides look the same on purpose: no frames (they read as a separate box), the same
`PaneHeader` (‹ ↑ path) on both, the same column headings, and a `PaneFrame` marker line under the
header that is blue on the active side. A thin full-height line divides them; its grip shows on
hover.

`qml/SplitPane.qml` is a self-contained second side (its own FolderListModel, path bar, selection,
drag and drop); the main side gives up `splitW` of its width. `activePane` says which side F5 / F6
copy / move from (`sendToOtherSide` → `Fm::copyOrMove`). Drags that start inside fm set
`internalDrag`; drops then go through `Fm::dropInternal`, which moves on the same disk and copies
across disks or when Ctrl is held (`QGuiApplication::queryKeyboardModifiers`). Drags from other apps
keep their proposed action. A narrow list (`compactList`) hides its Date column. The divider
(`splitDivider`) sets `splitRatio` (the main side's share, 0.22–0.78, saved); `splitW`'s animation
is off while dragging (`draggingSplit`) so the sides follow the pointer.

The split side has **its own tabs** (`SplitPane.tabs` / `tabIndex`, same snapshot idea as the
main side, simpler state: folder + back history) and its own `TabStrip` at the same height as the
main one. Tab keys, the File menu and sidebar places go through `activeNewTab`, `activeCloseTab`,
`activeCycleTab`, `activeJumpTab`, `activeReopenTab` and `activatePlace`, which pick the active
side (`splitActive`). Closing the split side's last tab closes the split view. Its tabs are saved
as `splitTabsJson` (session window only).

Each side has its own view (`splitViewMode`) and icon size (`splitWheelValue`, saved; the split
pane's `k`, `cellSize` and `iconSize` come from `splitIconScale`). The thumbwheel shows
`activeWheel` and writes through `setActiveWheel`, so it, the home button, View ▸ icon sizes and
Ctrl+/- act on the active side; Ctrl+wheel over a side makes that side active first
(`SplitPane.zoomRequested`).

### Terminal tabs

A real Alacritty window can't be embedded on Wayland, so fm has its own terminal:
`src/terminal.{h,cpp}`, a `QQuickPaintedItem` (`TerminalView`, registered as `IrixFm 1.0`) that
runs the program in a `KPtyProcess` and feeds its output to **libvterm** (the engine behind
Neovim's `:terminal`). It paints the libvterm screen with the Alacritty look (Noto Sans Mono 12,
Nord palette, bold = bright colours, background alpha .8, underline cursor; all as in the user's alacritty.toml), keeps 10000 lines of scrollback, does
selection, Ctrl+Shift+C/V, bracketed paste and mouse reporting. It accepts `ShortcutOverride` for
every key except Ctrl+Shift+…, Ctrl+PgUp/PgDn/Tab and Alt+1…9, so Ctrl+C, Ctrl+W etc. reach the
program while tab switching still works.

The window owns all terminals (`terminals` map by id, `createTerminal` parents them into the
side's `termLayer`); a tab with `term`/`termId` shows its terminal instead of the folder view
(`activeTermId`, `termActive`). Terminal tabs aren't persisted. When the program exits
(`finished`), its tab closes. Tab titles come from the program (OSC 0/2) via `termTitle`.

Font size: `TerminalView::event` takes `QEvent::NativeGesture` (`ZoomNativeGesture`, the touchpad
pinch; KWin/Wayland sends it as a native gesture, not as touch points) and calls
`zoomBy(1 + value)`; Ctrl+wheel and Ctrl++/-/0 do the same (these keys are taken in
`ShortcutOverride`, as Alacritty does). `setFontSize` clamps to 6–48 pt, re-measures the cell,
resizes the vterm (the program gets SIGWINCH) and shows "N pt" for 1.2 s. The last size is
`s_lastPointSize`, used by new terminals (not saved across restarts).

Drops: the item has `ItemAcceptsDrops`; `dropEvent` types the local paths shell-quoted, inside a
bracketed paste, and reports `CopyAction`, so the source never deletes anything. The folder
`DropArea`s behind a terminal are disabled while it shows (`enabled: !termActive`).

### The dock

A Plasma panel set to "Windows Go Below" (or auto-hide) doesn't reserve space, so a maximized
window extends under it. `Fm::readDockReserve()` reads bottom panels (location 4) from
`plasma-org.kde.plasma.desktop-appletsrc` + `plasmashellrc` (thickness, floating, visibility) and
`Fm.dockReserve` = thickness + 16 (floating) or + 4. `~/.config` is watched (KConfig replaces files
on save), so resizing the dock updates fm at once. `win.dockInset` applies it only when maximized or
full screen: on Wayland a window doesn't know its position, so a merely large window can't be
detected. The tab bar, status bar, sidebar and panes all end `dockInset` higher.

### Rich previews

`Fm::richPreview(path)` returns `{kind, html, language}`. Markdown: fenced code blocks are cut out
and highlighted by their language, the rest goes through Qt's own Markdown renderer
(`QTextDocument::setMarkdown`, GitHub dialect) and is stitched back together; links get Nord frost,
pictures resolve next to the file and are scaled to 640 px. Code files: KSyntaxHighlighting picks
the definition by file name (then MIME type) and a small `AbstractHighlighter` subclass writes
coloured `<span>`s with the **Nord** theme. Quick Look shows it in a `TextArea` (RichText); the
preview pane shows the first 4 KB without pictures.

### Active side, transparency, bottom section

- `splitActive` decides where keys and commands go: the split side has its own `viewMode`
  (`splitViewMode`, its own `GridView` with the IRIX icons), `moveCursor`, `focusedPath`,
  `selectAll`; `activePaths()` / `activeFocusedPath()` feed Quick Look, Get Info, Copy and the
  preview pane; the toolbar view buttons show and set `activeViewMode`.
- `glassAlpha` (View ▸ Transparency, saved) drives `bodyTint`, `sidebarTint` and `pillTint`.
- `bottomExtra` (dragged on `bottomHandle`, saved) lifts the tab bar and status bar on top of the
  dock reserve (`bottomLift = dockInset + bottomExtra`).
- The window shadow's corner tiles reach `radius` into the window and the window shape is cut out
  of the shadow image, so the bottom corners (where the shadow is strongest) look like the top
  ones; the window and sidebar edges are also lit at the bottom (`EdgeRing.bottomAlpha`).

### Sidebar sections

Sections are part of `places` (title, colour, items) and can be created, renamed, moved and
removed (`newSection`, `renameSection`, …); only Tags is fixed. Folding is saved by title
(`collapsedJson`); a header after a folded section gets a small gap (`afterFolded`), so folded
sections stack.

### Settings

`QtCore.Settings` in category `fm` → `~/.config/irixfm/irixfm.conf`: icon size (thumbwheel value),
view mode, hidden files, window size, sidebar (`places`, JSON), sort field and order, sidebar
and preview visibility, Calculate All Sizes, Recent Folders, search scope. All running fm windows share and overwrite it.

## Workflow

```
make test install && pkill -x irixfm; irixfm ~ &
```

QML is loaded from disk at start (no resources compiled in), so QML-only changes need `make install`
and a restart, not a rebuild. `make run` uses the source tree directly (`IRIXFM_ASSETS`).

Check the look without opening a window on someone's screen (`offscreen` matters: a real window
can get clicks or keys from the user during the 2.5 s before the snapshot):

```
XDG_CONFIG_HOME=$(mktemp -d) QT_QPA_PLATFORM=offscreen IRIXFM_SNAPSHOT=/tmp/fm.png irixfm ~/Pictures
```

The snapshot has transparent glass (the blur comes from KWin), so composite it over a blurred
wallpaper to judge it, e.g.
`magick bg.png -blur 0x30 -gravity center -crop WxH+0+0 +repage fm.png -composite out.png`.

## Gotchas

- **Qt logs to the journal**, not the terminal, when started from a desktop session. Use
  `QT_FORCE_STDERR_LOGGING=1` to see QML errors; a QML syntax error makes `irixfm` exit with code 1
  and no output otherwise.
- **`QtCore.Settings` needs an organisation name** (`app.setOrganizationName`), or it silently fails
  to initialise.
- **`Kirigami.Icon` rounds to standard icon sizes** (48 px) unless `roundToIconSize: false`.
- **`onTriggered: for (...) ...` is a syntax error** in QML; a statement like `for` needs braces.
- **`Shortcut { sequence: StandardKey.Copy }`** warns when the key has several bindings; use
  `sequences: [StandardKey.Copy]`.
- **Test settings leak**: anything that runs fm saves its settings. Tests and snapshots use a
  throwaway `XDG_CONFIG_HOME`, or a saved list view will hide the icon grid in the next run.
- **Item already has `top`** (an anchor line, FINAL): a delegate property called `top` makes the
  whole file fail to load. Same for ids that shadow window properties (`id: places` hid `win.places`).
- **`QMetaObject::invokeMethod` must pass every declared argument** of a QML function; a function
  with an optional parameter isn't found when called with none. Tests press keys instead.
- **Off-screen tests need an active window** for keyboard focus (`requestActivate()` +
  `QTest::qWaitForWindowActive`), and `QTest::keyClicks` only takes widgets.
- **Key combinations in tests must go through `QTest::keyClick`**: a `QKeyEvent` sent straight to the
  window reaches `Keys` handlers but not QML `Shortcut`s.
- **A Get Info window takes the keyboard**; tests close it and re-activate the main window.
- **`FolderListModel.SortField` starts at `Unsorted` = 0** (Name 1, Time 2, Size 3, Type 4); use the
  enum names in QML and these numbers from C++.
- **An inactive `Loader` still takes room in a `Row`** unless it's `visible: false` — that pushed the
  list view's Size/Date/Kind values off-screen.
- **The tab switch reports the old folder as Ready**: FolderListModel keeps `Ready` until it starts
  loading the new folder, so restoring a scroll position waits for `Loading` (`waitForLoad`).
- **Tests get their own `XDG_CACHE_HOME`** (Makefile), so they never write into the real size cache.
- **Tests that trash files must live on the home disk** and use a private `XDG_DATA_HOME`;
  `IRIXFM_NO_DIALOGS=1` makes job errors print instead of opening (blocking) dialogs.
- **`stdout` is buffered when piped**: tests call `setvbuf(stdout, nullptr, _IONBF, 0)` so a hang
  still shows how far they got.
- **ListView delegates are children of `contentItem`**, not of the view, when looking them up from C++.
- **A component's own `dir` must not be bound to a setting it writes back** (SplitPane: binding
  loop); set it once in `Component.onCompleted`, then save on change.
- **Menus already have `title`** (FINAL): a custom `title` property on a `P.Menu` fails the whole
  file. Same family as `Item.top`.
- **Middle-click needs `Qt.MiddleButton` in `acceptedButtons`**, and a MouseArea can set
  `acceptedButtons` only once.
- **Repo images** must not contain copyrighted wallpapers; `docs/bg.jpg` is a generated gradient.

### Sidebar icons

An entry's icon is `item.icon` in the places JSON: `"emoji:🏠"` (drawn with Noto Color Emoji) or an
icon-theme name (an app's icon, from `Fm::applications()`). Without one, `standardPlaceIcon(item)`
picks a `-symbolic` theme icon from the path or action (`~` → user-home, `Downloads` →
folder-download, trash, network, …; `folder-symbolic` otherwise), drawn with `isMask` in the
section's colour. `IconPicker.qml` (Emoji / App Icons, search, Standard Icon) sets it through
`placeSetIcon(si, ii, icon)`.

### Terminal details

- The shell is the **login shell** from the user database (`getpwuid`), not `$SHELL`: fm may be
  started from another shell (a tool, a script) whose `$SHELL` differs. It's also exported as
  `SHELL`, so tmux started inside uses it. `IRIXFM_SHELL` overrides it (the tests use bash).
- The thumbwheel sizes the active terminal's text while one shows (6–30 pt); its button calls
  `fitWidth()`: the largest size ≤ 12 pt at which the longest visible logical line (rows joined by
  libvterm's `continuation` flag) fits, animated (`QVariantAnimation`) while libvterm re-flows
  (`vterm_screen_enable_reflow`). `termFontSize` is saved for new terminals.
- `go()` on a side with a terminal calls `changeDirectory(path)`: only when the shell itself is the
  pty's foreground process group (`tcgetpgrp`), so nvim / tmux / a running command are left alone.
  The other way round: 120 ms after output, the shell's cwd is read from `/proc/<pid>/cwd`
  (any shell, no OSC 7 needed); a change emits `currentDirectoryChanged` and
  `terminalCwdChanged` calls the side's `go()`. `changeDirectory` skips a path the shell is already
  in, so the two don't ping-pong.
- **Drops and pinches are taken at the window** (`eventFilter` on the `QQuickWindow`), before Qt
  Quick's own delivery. Before that, a drop on a terminal tab could land on the folder `DropArea`
  behind it and **move the file into the tab's folder**; those `DropArea`s are disabled while a
  terminal shows, and the terminal answers drops with `CopyAction`.
  `QT_LOGGING_RULES="irixfm.terminal.debug=true"` logs drags and pinches to the journal.
- Offscreen Qt (the tests) has no real `QDrag`: `exec()` returns at once, so drops are tested with
  synthetic `QDragEnterEvent` / `QDragMoveEvent` / `QDropEvent` sent to the window.

### Performance: terminal

`IRIXFM_TERM_BENCH=<dir> QT_QPA_PLATFORM=offscreen build/terminal_test` runs a benchmark instead
of the tests: a 200×60-cell terminal, throughput (`seq 1 200000`, `cat` of an 8 MB file,
`ls --color -la /usr/bin` ×5 until the prompt is back, with paint counts), `paint()` time of a
full screen (ls --color, a colour per cell, plain text, scrolled back; also at 1.5x) and the RSS
of a full 10000-line scrollback. It saves PNGs of the painted screens and of the window as
rendered to `<dir>`, to compare before / after (`magick compare -metric AE`).

- **paint()** draws all backgrounds first (one `fillRect` per run of cells with the same colour,
  whole pixels), then the text as one `QGlyphRun` per colour and style for the whole screen, each
  glyph at its cell (`QRawFont` per style, glyph cache). Cells the font lacks (glyph 0), wide and
  combined cells go through `drawText` as before, for font fallback. Per-cell `drawText` (a
  QString, a shaping pass and a font switch per cell) was most of the time. The output is
  pixel-identical. 200×60: ls screen 7–11 → 2 ms, plain text 25–38 → 3 ms, colour per cell
  33–50 → 8 ms.
- **Partial repaints**: libvterm damage and the cursor's old / new cell call `update(rect)`;
  `QQuickPaintedItem` clips the painter to the dirty area and `paint()` draws only those rows.
  Title changes (each prompt), key presses and focus changes no longer repaint everything.
  `terminal_test` checks that the rendered window still matches a full paint.
- **Scrollback** stores 20-byte cells (`SbCell`), not `VTermScreenCell` (40 bytes), without the
  trailing blank cells; combining characters go in `SbLine::more`. 10000 lines of ls --color at
  200 columns: 78.6 → 11.2 MB. Popped lines are filled with blanks in the *default* colours
  (`m_blank`); `VTermScreenCell{}` was opaque black.
- **Throughput is bounded by libvterm**: every line feed at the bottom memmoves the whole screen
  buffer (rows × cols × 36 bytes, `moverect_internal` in screen.c), about 20 µs per line at
  200×60. `seq 1 200000` is mostly that. Painting runs at most once per frame (`update()` is
  coalesced), now 1–3 ms a frame.
- Crashes fixed: `~TerminalView` sends SIGHUP (interactive bash ignores SIGTERM), waits, and
  deletes the `KPtyProcess` itself before `vterm_free`; left to `~QObject`, `~KPtyProcess` waited
  for the live shell and crashed in `KPty::logout`. libvterm 0.3.3 aborts ("screen_resize failed
  to update cursor position") when reflow pushes the wrapped line holding the cursor off the top:
  `reflowLosesCursor()` replays `resize_buffer()`'s row bookkeeping and such a resize is done
  without reflow. Zero-size (hidden) resizes and non-finite font sizes are ignored.

### Web tabs

`qml/BrowserView.qml` (Qt WebEngine; `QtWebEngineQuick::initialize()` runs first thing in
`main()`). It is created lazily with `Qt.createComponent` the first time a web tab opens, and
lives in the same `terminals` map as the terminals: it offers the same small API (`title`,
`start()`, `fontPointSize` / `setFontSize` / `fitWidth`, `finished`, `changeDirectory` → false), so
tabs, titles, Ctrl+Shift+W and the thumbwheel (zoom = pt / 12) need no special cases.
`browserActive` routes Ctrl+L and Back / Forward to the page. The profile is persistent
(`storageName: "irixfm"`, under `~/.local/share/irixfm/QtWebEngine/`). `Fm::openInFirefox`
starts Firefox with the page's URL. Tests: `tests/browser_test.cpp` (off-screen works with
`--disable-gpu`).

Terminal touchpad scrolling adds up `pixelDelta` (`m_wheelRest`) and scrolls a line per cell
height; dividing every small delta by the cell height on its own gave 0 lines, so touchpad
scrolling did nothing.
